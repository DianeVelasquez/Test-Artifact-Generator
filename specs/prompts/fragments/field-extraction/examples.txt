## KEY TAKEAWAYS FROM THE REAL-WORLD EXAMPLE

1.  **Synthesize Information:** You must connect data from multiple files. `serviceName` came from `build.json`, `messagingType` from `README.md`, and `operations` from a `.feature` file name.
2.  **Prioritize Sources:** Sometimes sources conflict. The `README.md` explicitly said `hasSpr: false`, even though `build.json` had an `SPR_URI`. The explicit statement in the README is a higher quality signal.
3.  **Infer from Structure:** The name of a `.feature` file or a directory can be a strong signal for the `operations` field.
4.  **Perform Transformations:** You must convert data to the correct type (e.g., "60 seconds" to the number `60000`).
5.  **Justify Everything:** Your `reasoning` is critical. It must explain *which* file and *what logic* you used to get the value.
